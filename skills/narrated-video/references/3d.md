# 3D scenes with Three.js

Answers: how to build a `space` scene, what you may and may not import, and
why camera moves work differently here than anywhere else.

## The GL renderer — the silent failure to check first

Headless Chromium does not enable a WebGL backend by default. A space scene
rendered without it produces a correctly sized, correctly timed video, exit code
0 — the 3D content is a **black rectangle** where the scene should be. Nothing in
the render log says so.

`nv sync` writes both halves: `--gl=angle` into every render and still script in
`package.json`, and `Config.setChromiumOpenGlRenderer("angle")` into
`remotion.config.ts`. It removes both when the last space scene goes, so a project
that stops rendering 3D stops forcing ANGLE on every frame. CHK-33 catches either
half going missing after the fact.

```ts
// remotion.config.ts — nv sync manages this
Config.setChromiumOpenGlRenderer("angle")
```

```json
// package.json scripts — nv sync manages these
"render": "remotion render Explainer out/explainer.mp4 --gl=angle",
"still":  "remotion still  Explainer out/explainer.png  --gl=angle"
```

If you are rendering through the SSR API, pass `chromiumOptions: { gl: "angle" }`
on `renderMedia`.

## The one rule that admits no exceptions

**Drive all animation from `useCurrentFrame()`. Never use `useFrame` from
`@react-three/fiber`.**

`useFrame` is a `requestAnimationFrame` loop. Remotion captures frames out of
order, in parallel browser tabs, each starting at a different wall-clock moment.
A `useFrame`-driven scene produces a *different video every render* — each
individual frame still looks fine, the gate exits 0, and the error is invisible
until someone renders twice and diffs the output.

`useCurrentFrame()` from `remotion` is the only time source a scene may touch.

## The `<Space>` component

Every space scene talks to `<Space>` from `kit/src/components/space.tsx`. The
component owns everything Three.js needs to do once per canvas:

- `ThreeCanvas` from `@remotion/three`, sized from `useVideoConfig()`.
- A transparent background, so `Stage`'s page tint shows through and the 3D
  content composites into the cut rather than replacing it.
- Default `ambientLight` and `directionalLight` derived from `THEME.foreground`,
  so the scene looks like it belongs to the palette without per-scene lighting
  decisions.

```tsx
import { Space } from "../components/space"

<Space name="Stack" camera={{ position: [0, 0, 5], fov: 60 }}>
  {/* frame-derived meshes */}
</Space>
```

The `camera` prop takes a `position: [x, y, z]` and an optional `fov` (degrees,
default 75). There is no `lookAt` — point the camera by positioning it; a
`lookAt` that moves is driven by `useCurrentFrame()` like everything else.

## Camera moves as fraction cues

A camera pull-back is a function of the frame, cued as a fraction of
`durationInFrames` — the same pattern every other reveal uses:

```tsx
const CUE = { pullBack: 0.55 }

const z = interpolate(
  frame,
  [at(CUE.pullBack, durationInFrames), durationInFrames],
  [4, 12],
  { extrapolateLeft: "clamp", extrapolateRight: "clamp" },
)

<Space name="Zoom" camera={{ position: [0, 0, z], fov: 60 }}>
```

This guarantees the Vietnamese cut re-times the camera move automatically when
its audio is longer — no hard-coded frame counts, no drift.

## What a space scene may import

| Allowed | Why |
| --- | --- |
| `remotion` — `useCurrentFrame`, `interpolate`, `useVideoConfig` | The frame source. |
| `../components/space` — `<Space>` | The one interface to Three.js. |
| `../components/primitives`, `../components/stage` | Layout and motion as always. |
| JSX Three.js element names — `<mesh>`, `<boxGeometry>`, `<meshStandardMaterial>` | react-three-fiber registers these; they reach the canvas through `<Space>`. |

| Forbidden | Why |
| --- | --- |
| `@react-three/fiber` | Direct import bypasses `<Space>` and its determinism guards — CHK-37 fires. |
| `three` | Same; a direct import lets `useFrame` in and no check can see it. |
| `@remotion/three` | `ThreeCanvas` lives inside `<Space>`; importing it again is a second canvas without the defaults. |

CHK-37 enforces this at validate time.

## The `@remotion/three` version

`@remotion/three` is pinned to the exact version `remotion` is on, never a range.
It depends on its own release of `remotion` exactly, so `^4.0.0` resolves to a
second copy of Remotion installed beside the pinned one — and two copies do not
share React context, which means the hooks inside `<Space>` read from the copy
that is not driving the render. Remotion prints a mismatch banner and renders
anyway, exit code 0.

The version is derived from the kit's own `package.json` rather than written a
second time, so it cannot drift, and CHK-38 fails when a hand-edit puts the
family back out of step.

## Render cost

A 3D scene is the first thing in this kit that can make a render take minutes
instead of seconds. `nv status`' duration estimate does not account for GPU time
— a complex scene with many meshes, high-resolution textures or expensive
shaders will exceed the estimate by a factor of five to ten.

Measure render time before committing to a complex scene. A headless Chromium
render with `--gl=angle` (the GL renderer CHK-33 will enforce) takes roughly
1–3 seconds per frame for a simple scene. A two-minute video at 30 fps is
3,600 frames — plan accordingly.

## Asset loading

A `space` scene loads 3D assets — `.glb` models, HDR environment maps, textures —
asynchronously. Remotion's frame capture is synchronous: it does not wait for an
asset to finish loading unless you tell it to. Without the hold, the render produces
frames where the model is absent, and how many frames are affected depends on disk
cache and machine load — so the failure reproduces on CI and not locally, or the
reverse.

**Use `staticFile()`** for every asset path. A bare relative path (`"./model.glb"`) or
an external URL (`"https://cdn.example.com/model.glb"`) breaks the render: the
relative path resolves differently in different Remotion contexts, and an external URL
makes the render depend on network availability. `staticFile(path)` resolves to the
correct URL in Studio, `still`, and headless render.

Assets must live under `public/`. CHK-31 checks that every path passed to
`staticFile()` exists on disk at `public/<path>` before the render starts.

**Wrap every load in `delayRender`/`continueRender`.** Release the handle on both
the success path and the error path. A load that fails without releasing its handle
hangs the render process instead of failing it fast.

```tsx
import { delayRender, continueRender, staticFile } from "remotion"
import { useGLTF } from "@react-three/drei"

const handle = delayRender()

function Model() {
  const { scene } = useGLTF(
    staticFile("model.glb"),
    true,
    true,
    () => continueRender(handle),
    () => continueRender(handle),
  )
  return <primitive object={scene} />
}
```

`@remotion/three` exposes `useDelayRender`, which encapsulates the pair:

```tsx
import { useDelayRender } from "@remotion/three"

function Model({ src }: { src: string }) {
  const resume = useDelayRender()
  useGLTF(staticFile(src), true, true, resume, resume)
}
```

CHK-35 flags bare asset paths, external URLs, and `delayRender` calls with no
matching `continueRender` in source. CHK-31 flags a `staticFile()` path that does
not exist under `public/`. Both fire before the render starts.

## Adding a space scene

```bash
nv init --scene Stack --kind space
bun install
```

Then replace the placeholder mesh in `src/scenes/Stack.tsx` with your geometry,
drive all positions and rotations from `useCurrentFrame()`, and run `nv validate`.
